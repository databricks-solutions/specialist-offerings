# Detailed Format Conversion Steps

## Zeppelin .json to Databricks .py

### Zeppelin Notebook JSON Structure

```json
{
  "paragraphs": [
    {
      "title": "Load Data",
      "text": "%pyspark\ndf = spark.read.parquet('s3://bucket/data')\ndf.show()",
      "config": {
        "title": true,
        "enabled": true,
        "editorHide": false,
        "tableHide": false
      },
      "settings": {
        "params": {},
        "forms": {}
      }
    },
    {
      "text": "%spark.sql\nSELECT * FROM my_table LIMIT 10",
      "config": {}
    },
    {
      "text": "%md\n## Analysis Results\nThis section shows the key findings.",
      "config": {}
    }
  ],
  "name": "My Notebook",
  "id": "2ABC123",
  "noteParams": {},
  "noteForms": {}
}
```

### Conversion Process

1. **Parse the JSON** and extract the `paragraphs` array
2. **For each paragraph**, extract the interpreter prefix and code:
   - Split `text` on the first newline
   - First line contains the interpreter (e.g., `%pyspark`)
   - Remaining lines are the code
3. **Map interpreters** to Databricks magic commands (see magic-commands.md)
4. **Combine** into a single `.py` file with Databricks cell separators

### Output Format (Databricks .py notebook)

```python
# Databricks notebook source

# MAGIC %md
# MAGIC # My Notebook

# COMMAND ----------

# MAGIC %md
# MAGIC ## Load Data

# COMMAND ----------

df = spark.read.parquet('s3://bucket/data')
df.show()

# COMMAND ----------

# MAGIC %sql
# MAGIC SELECT * FROM my_table LIMIT 10

# COMMAND ----------

# MAGIC %md
# MAGIC ## Analysis Results
# MAGIC This section shows the key findings.
```

### Handling Paragraph Settings

- **title**: If `config.title` is true, add a markdown cell before the code with `## <title>`
- **editorHide**: If true, the code was hidden in Zeppelin -- add a comment noting this
- **tableHide**: If true, output was hidden -- no action needed (Databricks handles output separately)
- **enabled**: If false, the paragraph was disabled -- comment out the code

### Handling Zeppelin Forms (Dynamic Parameters)

```python
# Zeppelin form in paragraph settings:
# "forms": {
#   "name": {"type": "TextBox", "name": "name", "defaultValue": "default"},
#   "env": {"type": "Select", "name": "env", "defaultValue": "dev",
#           "options": [{"value": "dev"}, {"value": "prod"}]}
# }

# Convert to Databricks widgets:
dbutils.widgets.text("name", "default", "name")
dbutils.widgets.dropdown("env", "dev", ["dev", "prod"], "env")
```

## Jupyter .ipynb to Databricks

### Option 1: Direct Import (Recommended)

1. In Databricks workspace, navigate to target folder
2. Click **Import**
3. Select **File** and choose the `.ipynb` file
4. Databricks automatically converts:
   - Code cells become Python cells
   - Markdown cells become `%md` cells
   - Cell outputs are **NOT** imported (re-run notebook to regenerate)

### Option 2: Export as .py Then Import

```bash
# Using jupyter nbconvert
jupyter nbconvert --to script my_notebook.ipynb

# This creates my_notebook.py
# Then import into Databricks as a Python file
```

### Handling Kernel Metadata

Jupyter notebooks have kernel metadata (`kernelspec`):
```json
{
  "kernelspec": {
    "display_name": "PySpark",
    "language": "python",
    "name": "pysparkkernel"
  }
}
```

- **PySpark kernel**: Default in Databricks -- no changes needed
- **Python 3 kernel**: Works as-is; add `%pip install` for non-Spark libraries
- **Scala/Spark kernel**: Change default language to Scala in Databricks notebook
- **R kernel**: Change default language to R in Databricks notebook

### Cell Output Handling

- Databricks does **NOT** import cell outputs from `.ipynb` files
- All outputs must be regenerated by re-running the notebook
- This is actually beneficial -- ensures outputs match the Databricks environment
- For notebooks with long-running cells, consider breaking into smaller cells
